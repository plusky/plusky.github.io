1. Each job asks three questions in one chat. Turn 2 and turn 3 repeat the whole earlier conversation, so most of their prompt is already in the cache of the server that answered turn 1.
  2. Before: nginx with least_conn, where ties fall back to round robin.
    1. Turn 1 goes to server A and is read fresh.
    2. Turn 2 goes to server B, which has no cached prompt and reads everything fresh.
    3. Turn 3 goes to server C, which also reads everything fresh.
  3. After: nginx with hash $http_x_openqa_job consistent, keyed on the job id the script sends in the X-Openqa-Job header.
    1. All three turns go to server A.
    2. Turns 2 and 3 take 95% of their prompt tokens from the cache.
    3. If the server answers 503, the request passes to the next server.
