1. A test job fails on openQA. If no known issue matches, the job-done hook runs openqa-llm-investigate.
  2. The script builds one prompt from:
    1. the failure analysis of the job's log, with earlier reviews of runs failing in the same module
    2. the settings difference to the last good job
    3. the test commits since the last good job
  3. It asks a llama.cpp server running Gemma 4 E4B (three hosts behind nginx) three questions in one chat:
    1. question 1: the analysis, one line per failed module
    2. question 2: a summary of at most two sentences
    3. question 3: the verdict, with the job statistics
  4. The script posts a comment on the job that ends with three lines:
    1. Classification: Product bug | Test issue | Infrastructure problem. Only people read it; they reviewed 2.2% of the commented jobs.
    2. BISECT: YES | NO. On YES the hook starts openqa-investigate (a retry and reruns with the last good tests and build) and then openqa-trigger-bisect-jobs. This is the only answer wired to anything.
    3. Restart: YES | NO. Not connected: nothing acts on it.
